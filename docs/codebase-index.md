## Key relationships

- Browser authentication uses `lib/firebase/client.ts`; Next.js server sessions use `lib/firebase/admin.ts` through `lib/auth/session.ts`.
- `app/api/auth/session/route.ts` exposes the session operations implemented by `lib/auth/session.ts`.
- Protected server pages call `getCurrentUser()`; `proxy.ts` only redirects based on cookie presence.
- Browser backend calls send a Firebase ID token; `finapp/backend/Program.cs` validates it as a Bearer token.
- `AppDbContext` maps `User.DefaultTenantId` to `Tenant.Id`; migrations are the deployed schema history.
- `.github/workflows/frontend.yml` and `.github/workflows/backend.yml` validate their corresponding application directories.
